## 当前问题与应达到的结果

当前有322条竞对结构缓存、343份本地草稿，343份都带`source_slot`，54份含`manual_script`。本轮逐文件统计发现，草稿顶层均无统一的`prompt_version`、`prompt_hash`、`generation_meta`、`quality_evaluation`、`feedback`或`creative_brief`。这说明已有来源绑定和人工修改资料，尚未建立完整的版本—产出—评价链；不代表所有历史版本信息都不存在，生成批次的`settings.prompt_templates`已保存模板快照。

`prompt_settings.py`目前管理可切换版本，但同名另存可能更新已有内容；`prompt_builder.py`还包含模板外的硬编码规则。只记录v1/v2/v4名称无法完整复现生成条件。`server.py::generate_script()`已有JSON、时长、语速、素材范围及部分融合校验，`audit.passed`主要说明这些检查结果，不等于好口播、好创意或好投放。

`rival_visibility.py::hidden_ids()`会隐藏飞书标为“已使用”的竞对及其关联分镜/组件；`static/studio.js`默认开启此筛选。`build_slot()`和现有批次更侧重素材选择与去重，同一来源没有按风格、角度、叙事结构管理已尝试方向。把素材再次抽到，并不会自然产生新创意。

需要达到两个结果：

- 每次调提示词都能回答：改了什么、在哪些同条件样本上变好/退步、失败为何、是否值得替换、如何回滚。
- 同一竞对可以继续产出有证据支持、角度可区分的多个版本；知道已经做过哪些方向、还有哪些方向值得做、何时已缺少新空间。

## 产品闭环

```mermaid
flowchart LR
  A[竞对原稿与我方事实快照] --> B[AI拆解与创意覆盖规划]
  B --> C[不同创意任务与对应提示词版本]
  C --> D[生成与现有硬校验]
  D --> E[AI质量评审与同批差异检查]
  E --> F[推荐成稿与用户审稿反馈]
  F --> G[好样例与失败样例库]
  G --> H[固定测试集比较候选提示词]
  H --> I[推荐晋级或停用并保留回滚]
  I --> C
```

生成、评价、版本晋级是独立动作。日常生成不自动启动全套提示词搜索；评测结果也不自动写飞书。AI默认负责拆解、推荐任务和初评；人工选择是可覆盖的后备方式。

## 一、提示词怎样持续改进、怎样淘汰

### 版本可追溯

在现有设置上增加不可变的`prompt_bundle`：包含模板内容和内容哈希、模板版本、父版本、用途标签、修改说明，以及生成时的组装器/校验器版本或文件哈希。每次生成另存完整渲染System/User、实际输入事实快照、模型与参数、各次调用及修复情况。内容哈希与显示名称分离；同名修改生成新版本，不覆盖旧快照。

正式路由按任务选择，例如`单篇对照`、`多篇融合`、`一源多创/战术`、`一源多创/吐槽`，各有当前优胜版本。保留`candidate → evaluated → champion → retired`生命周期；`evaluated`仅表示已有有效评测，不能自动认定晋级。样本不足或评审分歧标记`insufficient_evidence`。停用退出默认推荐，历史稿、实验与回滚仍可访问。

强制事实范围、明确勾选、来源ID、输出契约与硬校验属于受保护规则，不交给优化器随意改写。先优化口吻、叙事组织、参考迁移等可编辑块。硬编码规则也计入版本指纹，避免模板没变而组装逻辑改变后误比较。

旧数据按可证明程度迁移：可唯一关联原批次的草稿，可以附上该批次模板快照的推导来源；无法恢复的标记`unknown`，不得把当前v4标到历史稿。模板可恢复也不代表当时组装器、模型和参数都能恢复，缺项必须明确。旧稿和人工字段原文件不批量重写，补充信息放独立索引。

### 反馈积累成可用的改进资料

结果卡和精修页增加轻量操作：采用、待修改、弃用；原因可多选“开头无吸引力、像说明书、口语别扭、事件不推进、来源没用好、套相同结构、事实无依据、同批重复”，也可点具体句子说明。记录人工修改前后版本及用户是否确认可作为偏好示例。

AI先给出缺陷分类、原文证据、可替换表达和改进建议；用户纠正一次即可成为一条反馈事件。收藏、保存、生成成功、写入飞书和人工修改都不能单独自动标成“高质量”。54份人工修改可用于建议候选样例，不自动当成54个正确答案；不把旧稿里的无依据玩法当我方事实。

失败分析分层：输入资料缺失、选材不合、组装规则冲突、提示词表达、模型波动、输出格式/校验、审稿偏好。每类都要有证据；素材事实不够不能靠加长提示词解决。

### 固定样本比较与评分

每个测试样本冻结来源原稿、关联资料、武器/强化/福利、明确勾选的玩法/关卡、任务角度、时长和模型参数。两个提示词使用完全相同的条件。首次可先做6个来源的小规模筛查，再扩成覆盖各模式和常见失败类型的样本集；不能凭6篇宣布长期胜出。

样例分为优化集、验证集、留出验收集。按竞对来源族分组；同源衍生稿、多篇融合共享来源的近邻样例不能跨组泄漏。优化器只看到优化集及允许的验证反馈，留出集原稿、答案和评审明细不进入搜索提示。候选反复试到测试集通过也会造成过拟合，应记录使用次数并轮换独立验收来源。

评价分三层，结果分别显示：

| 层级 | 检查内容 | 处理方式 |
|---|---|---|
| 必须满足的约束 | 现有JSON/镜头/时长/语速/素材范围；新增明确勾选一致性、来源映射和事实依据检查 | 规则失败直接不合格；语义事实疑点标记待核实，不能用口语分抵消 |
| 单篇编辑质量 | 开头吸引力、自然口语、事件/选择推进、可理解性、来源迁移、风格达成、画面可执行性 | AI按冻结rubric逐项打分，输出正文位置、证据短句与理由 |
| 同批创意差异 | 钩子前提、核心矛盾、决策理由、叙事顺序、情绪走向、结果落点 | 比较整批与该来源已采用稿；仅换同义词/武器名称不能算新角度 |

编辑质量初始各维度用1–5档并给出低/中/高分示例，不先宣称任意权重是客观真理。总分只做辅助排序；事实不合格、整体不可用和评分器不确定均单独显示。可用“预计开场时段的文字吸引力”，不能将字数位置估算当实测三秒视频效果。

比较采用隐藏版本名的A/B盲评，允许A好、B好、相当、都差、证据不足。随机左右顺序，对争议样本做对调复评；裁判不给候选的自评分或作者身份。裁判返回证据与简明原因，不要求或依赖模型内部思维链。作者和裁判可分开配置，优先选择经校准的裁判；换裁判/标准必须新建评测版本，不能混算旧分。

用用户真实取舍校准裁判；记录一致率、分歧案例及其来源，样本少时展示分母。对于带故事冲突的文案，不将“礼貌/完整教学”默认当优点。没有投放数据前，评价对象明确为编辑质量代理指标。后续接投放结果时另存素材版本、曝光、花费、受众、时段和样本量，避免将分配差异归咎于提示词。

### 优化与晋级

每次优化任务读取当前版本、典型失败样例、用户修改和受保护块，先提出2–3个有差异的局部修改候选，每个必须写“要解决的失败—修改位置—预期作用—可能回退”。用固定集测试，失败样例和退步也保留。达到调用次数/费用预算、时间上限或连续无改进即结束。

初期输出推荐版本及对照证据，用户可沿用现有“切换并生效”操作。后续再支持配置充分证据后的自动晋级/停用；不能因为单次AI均分高就覆盖生产提示词。正式晋级须：受保护约束不放宽，关键模式无明显回退，盲评胜率和人工校准达到预设门槛，且留出来源支持改进。

判定门槛在试验前冻结。建议先累计至少30个独立来源组的成对比较作为较正式判断的起点，同时报告来源组数、胜/平/负/都差、采样次数与按来源组计算的置信区间；30组仍不保证统计充分，区间跨过无改进、留出样本过少或关键风格回退时继续保留候选，不自动淘汰。多种风格分别比较，保留各自擅长的提示词，避免唯一总冠军把所有稿写成同一种腔调。

## 二、一条竞对怎样产出多篇真正不同的脚本

### 增加独立的“一源多创”入口

保留现有“单篇竞对—定向仿写”的对照用途。新入口在竞对详情/选中卡片中展示“围绕这条继续创作”，并提供“复用已有竞对”的列表。该入口生成同一来源的多条创意任务，不再让批次抽样把主来源轮换成别条。

复用需要明确的来源ID与复用范围。可以显示飞书“已使用”的标记，但不自动改飞书状态，也不全局关闭原有隐藏开关。专用接口应对明确选定的可读来源做复用授权校验；普通生成继续遵循原隐藏规则。缺失/无权限的来源不能被复用例外放行，来源不明的关联素材也不能补入。

### 先分析可迁移内容，再规划任务

对原稿做一次AI拆解，保存原文位置与内容哈希：钩子的前提、核心矛盾、选择与代价、转折、情绪推进、节奏和可迁移叙事功能。分清可借的表达组织、竞对独有且不能迁移的游戏机制，以及我方可支持的事实。缓存按来源内容、分析模板和模型配置的指纹失效，不反复付费分析相同内容。

然后规划4–6个候选创意任务；数量是上限目标，不是保证。每条任务必须给出角度、风格、核心矛盾、切入画面、叙事路径、采用的来源节拍、我方事实依据、与已有稿的具体差异，以及资料缺口。AI优先推荐支持充分且未覆盖的方向；可人工修改，事实不够时少做并说明原因。

| 候选方向 | 主要角度 | 风格 | 独立成稿需要的条件 |
|---|---|---|---|
| 危机里的选择 | 当前压力下为什么做这步 | 紧张实况 | 来源有对应压力节拍，我方素材可支撑应对；不编剩余秒数/血量 |
| 误判与纠正 | 一个看似合理的判断为何要调整 | 玩家吐槽 | 有可迁移的判断转折；不能凭空写“失败三次”的经历 |
| 战术取舍 | 为什么放弃另一选择 | 冷静分析 | 有可解释的事实差异；不能虚构倍率和实测胜率 |
| 结果倒推 | 从一个已知变化倒推决策 | 悬念反差 | 结果有事实或实机依据；没有就不用这个方向 |
| 预期落差 | 对手/观众的预期与操作理由不同 | 轻松整活 | 只迁移叙述视角，拟人化不能被写成新游戏机制 |
| 小目标推进 | 把长危机改成眼前一步的目标 | 克制陪玩 | 小目标与实际操作可对应，不空喊“轻松通关” |

这些是任务维度示例，不是六套固定开头/句序。应先依据来源独特内容选方向，再选合适风格；不要穷举“六风格×十角度”制造大量无意义稿。对照仿写可固定母稿句序；一源多创允许调整节拍和视角，但每篇仍显示从来源何处转化而来。

默认先一次规划，再逐篇生成。各篇有独立brief与参数，可选择不同的适配提示词；素材范围冻结，玩法和关卡仍须明确勾选。可配置同一事实素材下探索不同表达，也可明确选择不同武器范围做不同任务；提示词A/B比较则必须保持事实相同，不能把选材变化误算成提示词提升。

### 管理创意覆盖和重复

来源用`source_record_id + source_content_hash`识别；变体用`source_id + brief_hash + prompt_bundle_hash`追踪。每个来源展示“生成过、通过检查、已采用、已写回”的数量及覆盖矩阵，四者不能混成使用次数。失败或弃用稿保留尝试与原因，不能占满“已采用角度”；同方向用户仍可明确重做。

质量评审后做两段去重：文字n-gram/相似度发现近重复，AI再检查是否只是换词，或已经改变核心矛盾、决策理由及情绪走向。中文专名和必需玩法词不作为重复定罪依据。已有连续5字检查保留为现有多篇融合规则，新的一源多创需单独校准，不能把该规则泛化为所有模式的创意判断。

相似只标记而不自动无限重抽。显示最接近的旧稿、重复位置和区别不足之处，允许按用户指令修改该条；不自动重跑整批。素材已经难以支撑新角度时展示“剩余方向证据不足”，而不是把换词稿算作新增创意。

文字资料只能支持文案规划；涉及跨来源画面、实机效果与通关结果时继续保留原项目的验证边界。分镜沿同源连续链引用，调整叙事顺序也不能伪装成真实连贯实录。

## 三、怎样接入现有实现

### 模块与文件边界

| 位置 | 计划改动 |
|---|---|
| `prompt_settings.py` | 在现有revision并发保护上增加不可变快照、用途标签和启用指针；兼容现有`/api/prompts` |
| 新`prompt_registry.py`、`feedback_store.py` | 内容寻址版本、生成溯源索引、追加式反馈事件、原子写及revision冲突保护 |

| `static/studio.js`、`static/index.html` | 竞对详情的一源多创入口、brief预览、变体结果与覆盖展示 |
| `tests/` | 增加版本并发/回滚、隔离保存、来源例外范围、预算及差异判定的有意义测试 |

普通批次不改变按素材去重的现有含义。一源多创先冻结同一主来源及事实快照，每个item保存自己的brief和提示词快照，再复用现有逐篇队列、状态显示和草稿精修。已有批次/重试继续使用已接受的组合；不会将旧批次重解释为新创意任务。当前单进程锁应覆盖新付费评测/优化与生成任务，避免各模块各开一条不受控调用队列。

### 建议数据与接口

新数据均在本地独立目录，以下是设计名称：

```text
data_cache/
  prompt_registry/         # 不可变模板bundle与启用指针
  generation_traces/       # 渲染输入、参数、各次调用、输出哈希
  editorial_feedback/     # 人工/AI反馈事件，绑定正文版本
  creative_sources/       # 来源分析缓存与内容指纹
  creative_families/      # brief、变体、覆盖与接受状态
  evaluation_datasets/   # 冻结样本、来源分组与split
  evaluation_jobs/       # 候选输出、裁判结果、费用与停止原因
```

草稿可追加`generation_meta`、`creative_meta`和评价引用，但原有`full_script/shots/source_slot/manual_script/manual_shots`字段保持含义；反馈须指向正文哈希和`_edit_revision`，防止人工改稿后继续展示旧AI稿评分。精修后AI原稿与人工稿可分别评测。保存/写回适配器仅传现有业务字段，新增本地元信息不直接映射为飞书新字段。

拟新增接口：`GET /api/prompt-lab/versions`、`POST /api/prompt-lab/candidates`、`POST /api/prompt-lab/experiments`、实验查询/停止、`POST /api/prompt-lab/feedback`及版本启用/回滚；`GET /api/creative/sources`、`POST /api/creative/plan`、`POST /api/creative/batches`和来源覆盖查询。最终命名可按代码结构微调，但计划必须与正式API区别展示。候选生成、AI分析和实验执行属于付费动作，普通GET列表不能隐式触发。

### 工具接入与费用控制

第一期使用现有`call_ai`、模型配置、前端和本地文件存储，先补数据链。第二期引入Promptfoo离线评测适配；第三期GEPA通过adapter调用同一评测器，避免训练一套标准、线上另一套标准。现有Windows环境实测Node v24.15.0、Python3.14.4；这仅是运行时盘点，尚未安装或验证第三方库兼容性。接入时固定经验证的依赖版本，不把网站当前示例模型写死到产品。

每次运行先展示生成器、裁判、优化器各使用哪个模型/服务，样例数、候选数、预计及上限调用次数；有已配置价格时估算金额，无价格则明确无法估算金额。所有调用经过统一计数器，包含规划、初稿、现有自动修复、裁判、顺序复评与优化器反思。不能把GEPA的`max_metric_calls`直接当总模型调用数。

例如一次小筛查：6个冻结样例×2个版本×1次采样=12次生成，6次成对评审，基础18次；若各稿最多一次现有修复且6组都做一次对调复评，上限36次，不含另外开启的规划/反思。执行前冻结上限，预算不足则停止并标记未完成；不在后台无限重试，失败付费请求不自动重发。已缓存结果复用时显示缓存标记、原调用时间与对应模型，模型漂移或参数改变不得冒充同一实验。

实验输出只写实验目录，不能进入正式草稿/素材使用计数；用户采用候选后才通过现有保存流程另存新稿。重启后将未结束任务标记中断，恢复前检查已提交调用状态，避免重复计费。模型/第三方库升级后需重跑回归；停用规则和预算修改本身要留日志。

## 四、实施顺序与验收门槛

### 第一阶段：版本溯源、轻反馈、一源多创最小闭环

任务顺序：新增生成版本索引 → 结果/精修反馈 → 明确来源的拆解与brief规划 → 同源变体批次 → 覆盖记录。首批使用少量真实来源，根据证据生成最多4–6个任务；可先只选其中3个成稿。复用“已使用”来源通过专用入口和明确范围，不改变普通隐藏行为。

验收：现有115项测试继续通过；新旧草稿均可编辑/预览，人工稿不覆盖；普通模式无brief时兼容；新稿能追到准确bundle/事实/模型；选一个来源后各item主来源一致而brief有实质差异；未勾选玩法/关卡依然不注入；重复采用/保存不重复占覆盖单元；缺乏事实时明确不生成对应方向。

真实浏览器验证入口、规划预览、逐篇进度、覆盖与精修；真实模型小批次独立记录花费与失败，不以mock判定“角度有效”。一期可收反馈与看覆盖，不宣称已有自动淘汰能力。

### 第二阶段：固定样本、评分器校准、提示词对照实验

任务顺序：构建冻结样例与split → hard checks适配 → AI盲评与差异评审 → Promptfoo导出/provider/结果导入 → 实验对照页和回滚入口。先用小集验证流程，再扩到足够来源；人工偏好与AI评审的一致性单独出报告。

验收：同一实验各版本输入一致；相同请求指纹能追踪缓存与真实调用；裁判看到的版本匿名；能展示“都差、退步、证据不足”；评测标准和模型变化不混算；实验不生成正式草稿、不增加素材使用次数；预算包含修复和复评；真实模型对照有可读报告，改了什么与改善样例可直接核对。

### 第三阶段：GEPA候选搜索与按用途晋级/停用

任务顺序：GEPA适配 → 从失败样例产生局部候选 → 有上限搜索 → 来源组验证 → 版本推荐、停用与回滚。首期先推荐与人工启用，累计充分校准后再按配置开放自动晋级。保留不同任务/风格的优胜版本。

验收：优化器不能改受保护块或看到留出集；相同预算下能与当前版本比较；不改善时明确无改进并保留当前版；证据不足不自动停用；任务中断不重复付费；回滚能恢复确切bundle与路由，旧实验仍可复现或列明不可复现项。
