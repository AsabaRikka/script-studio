## 时间估算与交付目标

按用户指定的**Codex / GPT-6.1 Sol单主代理**在现有实现上连续迭代，首轮以**8–12小时有效工作**作为MVP工程预算；前两项完成后，约**累计3–5小时提供一源多创试用版**。每天可连续推进6–8小时的情况下，日历安排预留**1–2天**。这替代之前按人工开发估算的5–7个工作日，不缩减既定验收要求。

该范围是依据项目任务拆解的初步估算，尚无本项目完整MVP的实耗记录，不是模型速度基准或交付保证。按当前默认可用的运行方式估计，不假设Fast/Ultrafast、额外并行代理或无限调用额度。先完成1–2小时的溯源/反馈阶段，记录实际修改、测试和返工耗时，再修正剩余预算。服务/额度中断、等待审稿、等待正式服务可安全加载等外部停顿另计；任务不会在对话结束后自行按排期后台推进。

[官方模型资料](https://developers.openai.com/api/docs/models/gpt-6.1-sol)说明GPT-6.1 Sol面向复杂编码等任务；[官方模型使用说明](https://learn.chatgpt.com/docs/models)说明提高推理强度通常会增加耗时。官方资料没有给出本项目从任务量换算工期的依据，上述小时数均为本项目规划判断。

MVP交付后建议再经过1–2周日常使用积累审稿取舍，校准AI评分。这是使用观察期，不是要求用户等待两周才能使用，也不承诺该时间内已有统计充分的提示词淘汰结论。

首版须走通：选择竞对 → AI规划不同角度 → 逐篇生成 → 采用/弃用并记录原因 → 从失败反馈提出一个提示词候选 → 相同样例比较现用版与候选版 → 推荐选择、手动停用及回滚。AI默认做规划、评价和改进建议，用户可以覆盖判断。

## 功能定义

### 生成溯源与反馈

新生成记录关联不可变模板快照、组装器指纹、实际渲染提示、素材快照、模型参数及调用/修复记录。显示名可以沿用现有v1/v4等名称，内容哈希用于准确区分；保存同名新内容不能覆盖历史快照。侧边索引补充信息，原有草稿无需批量迁移。

结果区与精修页增加采用、待修改、弃用和可选原因。原因至少覆盖口语别扭、像说明书、开头弱、事件不推进、事实无依据、来源利用不足、与其他稿重复。反馈关联正文哈希和编辑revision，人工改稿后不误用原AI稿评价；人工修改可以提供候选案例，但不自动标成标准答案。

### 一源多创

用户选择一条竞对及现有素材范围；AI读取来源和我方事实，提出默认3个不同创意任务。每条显示角度、风格、核心矛盾、叙事路径、来源借用点、我方依据和资料缺口；可编辑、取消个别任务，最多6条。先完成任务预览，再执行逐篇生成；不会进入详情就自动付费调用。

AI按来源特征选择方向，不固定套“紧张/吐槽/战术”三类开头。资料不足时少做并解释，不能为凑数量编机制或结果。同一事实范围下可从压力、取舍、误判、预期落差等维度规划，但必须说明与其他任务的具体不同。

同源变体复用现有逐篇队列、结果展示、保存草稿和精修。主竞对固定，每个item保存独立brief和模板快照；重试沿用接受时的任务。来源详情显示生成过哪些方向、各稿是否采用，首版用列表与标签即可，不增加复杂覆盖矩阵。

普通模式的隐藏“已使用”规则保持。新入口可以明确选择可读的已使用来源复用，记录例外范围，不改飞书标记、不全局关闭隐藏；缺失、权限不可读及来源冲突仍拒绝。玩法/关卡未勾选不注入，人工稿和现有分镜同源连续性契约保留。

输出先走现有硬校验，再做轻量AI质量与同批差异检查。近似稿显示相似对象及原因，是否重做由明确操作触发；不存在自动无限换词重抽。采用的创意与失败尝试分开计数，重复保存不重复记账。

### 提示词实验

初始版本库沿用现有设置；增加按用途查看已有实验、生成候选、比较和停用/恢复的轻量入口。每次根据选定失败反馈提出**1个局部修改候选**，显示改动、原因与风险，不启动多轮自动搜索。

一次实验只比较现用版与一个候选，使用冻结的3–6个样例。各版本读取相同竞对、事实、时长、创意任务和模型参数，保留原始输出、失败与修复。样例来自可验证的来源快照；校验错误也属于实验结果，不能只统计成功稿。

AI裁判隐藏版本名称，按照口语自然、事件推进、开头吸引力、来源迁移、任务风格和事实疑点给证据。允许A更好、B更好、相当、都差和证据不足；存在分歧可显式对调复评，调用计入预算。评分标准/裁判模型版本冻结，不能把它们改变后得到的分数混算。

结果显示胜/平/负/都差数量、有效样本数、典型差异与未完成项。3–6个样例只是筛查，不展示“已证明普遍提升”的结论。用户可采用推荐候选，或把版本手动停用；历史快照保留，一键恢复旧版本。优胜按用途管理，不用一个均分淘汰所有风格。

## 接入及保护要求

主要扩展`prompt_settings.py`、`prompt_builder.py`、`server.py`及现有结果/精修/提示词设置；新增版本索引、反馈、creative planner与实验存储模块。新元信息放独立本地目录，旧接口和草稿字段保持兼容；实验候选不进入正式草稿和素材使用次数，只有采用后才通过原保存流程另存。

普通列表GET不隐式调用模型。任务执行前显示生成/裁判模型、样例数、调用数量和上限；有价格配置再显示金额，无价格则明确金额未知。预算包括规划、初稿、现有修复、裁判和复评；失败付费请求不自动重发。新任务共享现有业务任务锁，并保留停止与重启后中断记录，不自动恢复未确认调用。

本机服务继续复用，开发前检查正式任务和进程，不直接另起第二服务或重启。需要加载新后端时按既有保存页面、等待业务空闲、安全重启流程进行；没有完成这一步的代码不能称正式功能已启用。
